# RemoteOpsTool 远程执行性能基准测试

> 适用分支：`codex/优化架构`  
> 适用版本：以当前程序集版本为准，测试时必须记录提交 SHA  
> 目标：用统一口径验证冷启动、热会话、通道回退和各功能模块的实际性能，避免用单次耗时或主观体感判断优化效果。

---

## 1. 测试目标

本基准测试覆盖三类验证：

1. **正确性**：功能结果是否与原行为一致，是否出现重复执行、丢失输出、错误回退或破坏性操作重放。
2. **路由行为**：结构化查询是否优先走 WMI/DCOM，长脚本和交互程序是否按策略使用 PsExec，回退是否只发生在本机到目标机的传输失败场景。
3. **性能变化**：记录首输出时间、完成时间、P50/P95、输出字节数、回退率，以及冷启动和热会话之间的差异。

路由统计只保存主机、凭据指纹、操作、命令形态、通道和计数，不保存明文密码或命令文本。测试记录中也不得写入密码。

---

## 2. 测试环境准备

### 2.1 测试主机

至少准备以下目标类型：

| 类型 | 用途 |
|---|---|
| Windows Server，开启 WMI/DCOM 和 SMB | WMI 与 PsExec 同时可用的基线 |
| Windows 10/11 工作站，开启 WMI/DCOM 和 SMB | 普通终端、服务、打印机、交互桌面场景 |
| 仅允许 WMI/DCOM 的主机 | 验证 PsExec 不可用时的查询回退 |
| 仅允许 SMB/PsExec 的主机 | 验证 WMI 不可用时的命令和脚本回退 |
| 本机 localhost/127.0.0.1 | 验证禁止 PsExec 自连接及本机快速路径 |

每台目标主机需要记录：

- 主机名、IP、操作系统版本、域/工作组；
- 目标机系统负载；
- 445、135、5985/5986 端口的可达性；
- 目标账号类型：本地管理员、域管理员、普通域用户；
- 是否允许远程注册表、服务变更、SMB 管理共享；
- 当前 PsExec/PsExec64 版本和来源目录。

### 2.2 工具和信息

- 使用相同的 RemoteOpsTool 构建产物和 PsTools 版本。
- 关闭无关的高负载任务，或至少记录基线负载。
- 使用有线网络和稳定的 DNS/域控连接。
- 每轮测试前记录 `git rev-parse HEAD`。
- 建议每轮至少执行 5 次，冷启动场景单独执行，不与热会话数据混合。

### 2.3 统一记录字段

每个用例至少记录以下字段：

| 字段 | 说明 |
|---|---|
| 用例编号 | 例如 `CMD-01`、`SVC-03` |
| 提交/版本 | Git SHA、程序集版本、PsExec 版本 |
| 目标主机 | 主机名，不记录 IP 之外的敏感信息 |
| 凭据指纹 | 只记录程序显示的凭据指纹或测试编号 |
| 冷/热 | 首次操作、缓存过期后的操作或热会话操作 |
| 功能 | 终端、服务、注册表、软件、磁盘、进程、端口等 |
| 输入形态 | 短命令、长命令、脚本、交互 GUI、结构化查询 |
| 预期通道 | WMI/DCOM、PsExec、ScheduledTask 或本机路径 |
| 实际通道 | 从日志中的“远程执行通道”读取 |
| 是否回退 | 是否从首选通道切换到下一个通道 |
| 回退次数 | 本次顶层操作的传输失败次数 |
| 首输出时间 | 从操作开始到第一条远端输出/第一条成功日志 |
| 完成时间 | 从操作开始到 UI 结束等待 |
| 退出码 | 远端命令或 WMI 方法返回码 |
| 失败分类 | Timeout、Network、Authentication、PermissionDenied、RemoteCommand、Unknown 等 |
| 输出字节数 | stdout + stderr 的估算字节数 |
| 结果校验 | 与目标机手工查询或第二次独立查询对比 |
| 备注 | 环境异常、重试、缓存命中等 |

## 3. 基准场景矩阵

### 3.1 能力与缓存场景

| 编号 | 场景 | 操作 | 预期 |
|---|---|---|---|
| CAP-01 | 冷启动，目标同时支持 WMI 和 PsExec | 首次打开系统信息 | 只做该 operation 需要的探测，不应为只读查询提前启动 PsExec |
| CAP-02 | 热会话，同一主机同一凭据 | 连续打开系统信息、磁盘、服务 | 5 分钟内复用主机级能力快照，不重复完整探测 |
| CAP-03 | 凭据变化 | 先用账号 A 查询，再切换账号 B | A/B 缓存隔离，不错误复用 PsExec 可用性 |
| CAP-04 | 主机切换 | 在多个目标之间来回切换 | 旧主机的查询被取消，不把旧主机的路由结果套到新主机 |
| CAP-05 | 缓存过期 | 等待能力 TTL 后再次查询 | 只重探需要的 operation，不无条件全量探测 |
| CAP-06 | 失败冷却 | 让 PsExec 或 WMI 传输失败一次，立即再次操作 | 失败状态按 operation/transport 隔离，回退链仍保留 |

### 3.2 通道可用性场景

| 编号 | WMI/DCOM | PsExec | 操作 | 预期 |
|---|---|---|---|---|
| ROUTE-01 | 可用 | 可用 | 服务列表、磁盘、进程、注册表读取 | 优先 WMI/DCOM，不启动 PsExec |
| ROUTE-02 | 可用 | 不可用 | 短命令 `whoami`、查询类命令 | WMI/DCOM 成功，无 PsExec 等待 |
| ROUTE-03 | 不可用 | 可用 | 普通命令 | WMI 传输失败后回退 PsExec |
| ROUTE-04 | 不可用 | 可用 | 拖拽脚本 | PsExec 流式执行，输出和退出码正常 |
| ROUTE-05 | 不可用 | 不可用 | 任一功能 | 快速返回组合错误，不无限重试 |
| ROUTE-06 | 任一可用 | 任一可用 | 远端已启动但退出码非零 | 不换通道重放，保留原始退出码和错误 |
| ROUTE-07 | 可用 | 可用 | 超过 700 字符的有凭据命令 | 使用文件化或 WMI raw 路径，不得因本地 RunAs 命令行过长失败 |
| ROUTE-08 | 任意 | 任意 | `localhost`/`127.0.0.1` | 本机路径优先，不出现 PsExec 自连接 |

### 3.3 命令形态场景

| 编号 | 输入 | 预期 | 重点指标 |
|---|---|---|---|
| CMD-01 | `whoami` | 短命令完成，输出无重复 | 首输出、完成时间、退出码 |
| CMD-02 | `ipconfig /all` | 输出完整，回退不重复已有行 | 输出字节数、回退率 |
| CMD-03 | `Get-NetAdapter` | PowerShell 输出可读，CLIXML/空行被规范化 | 输出行数、错误分类 |
| CMD-04 | 700 字符边界命令 | 不接受非法截断，不丢失参数 | 实际通道、退出码 |
| CMD-05 | 超过 700 字符命令 | WMI raw 或文件化，不触发本地命令行限制 | 启动耗时、完成时间 |
| CMD-06 | 小脚本文件 | SMB 上传后 PsExec 流式执行 | 上传时间、首输出、退出码 |
| CMD-07 | 长时间脚本 | UI 进度持续更新，输出实时回传 | 首输出、心跳间隔、完成时间 |
| CMD-08 | 交互 GUI/MMC | 使用目标登录会话，重复点击不重复启动 | 会话 ID、启动结果、回退次数 |

### 3.4 功能模块场景

| 编号 | 功能 | 必测用例 | 关键验证 |
|---|---|---|---|

| SOFT-02 | 软件卸载/深度清理 | 已知卸载命令、失败、取消 | 只在传输失败回退，命令失败不重放 |
| DEV-01 | 设备列表/驱动 | 大量设备、驱动版本匹配 | O(n) 匹配，WMI 查询成功 |

## 4. 执行方法

### 4.1 冷启动与热会话

1. 清除或替换测试用 `%AppData%\RemoteAdmin\route-learning.json` 前先备份。
2. 重启程序，确认没有当前主机的能力缓存。
3. 执行目标用例，记录冷启动字段。
4. 不切换目标、不修改凭据，立即执行同一用例 5 次，记录热会话字段。
5. 等待能力 TTL 或手动刷新能力后重复一次，验证过期重探。

### 4.2 通道可用性控制

- 只允许 WMI/DCOM：临时阻断目标 SMB 445 或移除 PsExec 所需权限，确认不会把网络错误误分类为命令失败。
- 只允许 PsExec：临时阻断 WMI/DCOM 135/RPC 或调整目标机访问权限。
- 只有结构化查询可用：使用只允许 WMI 的账号，验证不会启动 PsExec。
- 只有命令通道可用：使用禁止远程 WMI 的账号，验证短命令和脚本回退。
- 测试结束后必须恢复目标机防火墙、共享、服务权限和账号权限，并记录恢复结果。

### 4.3 路由学习报表

程序运行一段时间后，可以读取 `%AppData%\RemoteAdmin\route-learning.json`：

```powershell
pwsh -NoProfile -File .\tools\Report-RouteLearning.ps1
```

导出 CSV：

```powershell
pwsh -NoProfile -File .\tools\Report-RouteLearning.ps1 `
  -Path "$env:APPDATA\RemoteAdmin\route-learning.json" `
  -ExportCsv ".\artifacts\route-learning-report.csv"
```

报表包含：主机、凭据指纹截断值、操作、命令形态、通道、总尝试、成功率、传输失败率、命令非零率、回退率、回退次数、P50/P95、平均首输出时间、输出字节数、最近失败类型和最后尝试时间。

## 5. 通过标准

### 5.1 功能正确性

- 所有功能性测试用例结果与目标机手工查询一致。
- 相同输入重复执行不会产生额外副作用。
- 远端命令已启动但返回非零时，不得换通道重放。
- 失败时错误信息包含通道、操作、错误分类和目标主机，不包含明文密码。
- 取消、超时和窗口关闭不会留下后台重复任务。

### 5.2 路由正确性

- 结构化只读查询不得无理由启动 PsExec。
- 需要实时输出、长脚本和交互 GUI 时，PsExec 的真实桌面和流式能力必须保留。
- 回退只发生在本机到目标机的传输失败场景。
- 能力缓存按主机、凭据指纹、operation 和 transport 隔离。
- 路由学习只改变首选顺序，不裁剪安全回退链。

### 5.3 性能门槛

绝对耗时受网络和目标机负载影响，因此以同环境同版本对比为准，建议使用以下相对门槛：

| 指标 | 目标 |
|---|---|
| 热会话能力探测 | 不再执行完整探测，缓存命中后额外等待小于 100 ms（不含目标功能本身） |
| 结构化查询 | 不因 PsExec 探测或 `PSEXESVC` 启动增加首屏等待 |
| 服务属性打开 | 不再串行执行多个独立 session/scope 查询，首屏等待明显低于修复前基线 |
| 服务重启 | 使用 200～500 ms 轮询，不出现固定等待导致的提前 start |
| 注册表多值键 | 往返次数随批量读取下降，P95 不高于修复前基线 |
| 回退输出 | 同一失败通道已经显示的行不在后续通道重复显示 |
| P95 | 在相同环境、相同目标、相同账号下相对基线不得回退超过 20% |
| 失败处理 | 传输失败快速进入下一通道；终端失败快速返回，不无限重试 |

如果 P95 回退超过 20%，先检查是否发生以下情况：

1. 目标机负载或网络抖动；
2. 能力缓存未命中；
3. PsExec 被不必要地用于结构化查询；
4. 回退链在远端命令失败后仍继续执行；
5. 每步都新建 session/scope；
6. 注册表或软件清单仍是 N+1 往返。

## 6. 结果记录模板

每个用例建议保存一行 CSV 数据，列建议如下：

```text
用例编号,提交/版本,目标主机,凭据编号,冷/热,功能,输入形态,预期通道,实际通道,是否回退,回退次数,首输出(ms),完成时间(ms),退出码,失败分类,输出字节数,结果校验,备注
```

汇总建议按以下维度统计：

- 按 operation：`Command`、`Inventory`、`RegistryRead`、`RegistryWrite`、`InteractiveLaunch`；
- 按 transport：`WmiDcom`、`PsExec`、`ScheduledTask`、本机；
- 按命令形态：短命令、长命令、脚本、交互程序；
- 按主机和凭据隔离维度；
- 冷启动与热会话分开统计；
- 成功、传输失败、命令非零和超时分别统计。

---

## 7. 注意事项

- 不要在报表、日志、截图和 CSV 中记录密码。
- 不要用单次最快结果代表整体性能，至少使用 5 次有效样本并记录 P50/P95。
- 不要把“网络错误”“认证失败”“远端命令返回非零”混为一类。
- 测试破坏性功能时必须使用隔离测试机，并准备恢复快照。
- 修改目标机防火墙、共享或服务权限后，必须立即恢复并记录。
- 若发现优化导致行为变化，应优先保证正确性和副作用安全，再判断是否调整路由。
